# Actina: как внедрить макет `site/` в рабочее демо

Ветка `actina-site`. Всё, что видно на http://127.0.0.1:8766/ у Бегзада, лежит в папке `site/`
и **не пересекается с рабочим демо** (`research/scripts/demo_static/`), поэтому при обычном
`git pull` ничего в рабочем демо не меняется. Нужно переносить руками (ниже, что и откуда).

## Как открыть макет

```bash
cd site && python3 -m http.server 8766
```

Открыть http://127.0.0.1:8766/ . Вход: любой номер телефона, код `1234`. Данные выдуманные,
состояние в `localStorage`. Модель `model.glb` — публичный набор figshare 26965903 (CC BY 4.0).

## Состав

- `index.html` — весь макет одним файлом (CSS, разметка, JS).
- `model.glb` — 3D-модель челюсти для макета.
- `slices/` — настоящие срезы КТ (демо-кейс client5): `mpr/` (три плоскости), `tooth/` (срезы зуба).

## Что есть в макете (по экранам)

| Экран | Что внутри |
|---|---|
| Главная | 3D-заставка, вход врача |
| Пациенты | 20 пациентов, фильтры (Записаны / Сегодня / Вчера / Ждут разбора / Подписано / Новые / Архив) со счётчиками, группы по дням, колонка записи на приём, поиск по имени, номеру карты и телефону |
| Карточка пациента | анкета, аллергия и лекарства, заметки врача, лента визитов, новый пациент и новый снимок боковыми панелями |
| Разбор КЛКТ | 3D с вращением, боковая панель «Сцена» слева (двигает модель, а не закрывает её), окраска по уровням / типу / квадрантам, блеск и прозрачность зубов, зубная карта FDI |
| Находки | 16 находок по специальностям, у каждой точное описание проблемы, основание и оговорка, подтвердить / отклонить с комментарием, смена уровня, подпись |
| Срезы | три КТ-среза с общим перекрестием; срезы зуба в карточке зуба |
| План | услуги по этапам лечения |
| Чат Actis | вопросы по снимку, голосовой ввод (иконка микрофона, расшифровка в поле, отправка стрелкой) |
| Профиль врача | данные, фото, язык RU / UZ |

## Что на что заменить в рабочем демо

Прямой замены «файл в файл» нет: макет работает на выдуманных данных в браузере, рабочее демо —
на настоящем сервере. Переносится вид и логика экрана, а данные берутся из API Батыра.

| Что в макете | Где искать у Батыра (проверить глазами) |
|---|---|
| Список пациентов, фильтры, группы | `patients.html`, `patient-bar.js` |
| Вход врача, профиль | `auth.js`, `doctor.js`, `home.html` |
| Панель «Сцена», разбор КЛКТ | `index.html` (3D-вьюер) |
| Язык RU / UZ | `i18n.js` |

## Что берём откуда (договорённость)

- **Сцена**: объединить обе. Из макета: боковая панель слева, окраска по квадрантам, блеск зубов. Из демо: изоляция зуба, слои, пульпа и каналы.
- **План лечения**: из макета.
- **Срезы зуба**: у Батыра настоящие, в макете подключены его картинки.
- **Чат**: макет (Actis) плюс голосовой ввод. Источник расшифровки заменить на API Батыра (сейчас встроенная в браузер распознавалка речи).
- **Находки**: из макета (точное описание проблемы, без плашек с числом и надёжностью).
- **Профиль и язык**: из макета, плюс удачные моменты профиля Батыра.

Общее правило переноса: добавлять функции, которых нет у второй стороны; там, где есть у обоих, выбирать лучшую реализацию, а не склеивать обе.
