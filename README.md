# Actina — AI-разбор стоматологических снимков

Система читает снимок, находит на нём измеримые факты и показывает врачу,
**на чём каждый вывод основан**. Диагноз ставит и подписывает врач.

Делается для клиники в Нукусе (Узбекистан), поэтому код, комментарии и
интерфейс — на русском. Историческое имя проекта в журнале и в именах файлов —
*Stomadent*.

## Что работает

Три независимых трека. Числа ниже — замеры из рабочего журнала `CLAUDE.md`,
каждый с указанием выборки; где проверки на чужих данных не было, так и
написано.

| Трек | Вход | Модель | Качество |
|---|---|---|---|
| **КЛКТ (3D)** | DICOM-серия, 300–600 МБ | nnU-Net v2 3d_fullres | Зубы: полнота **100%**, точность **96.5%**, Dice медиана **0.939** — внешняя проверка на DentVoxel, 25 томов, 724 зуба, модель этих данных не видела |
| **Каналы** | вырез зуба 128×64×64 | 3D U-Net на своей нарезке | Dice **0.922**, ошибка дохода до верхушки **0.009** (648 вырезов проверочной доли) |
| **Панорамы (2D)** | ОПТГ, PNG/DICOM | ансамбль YOLO12x + YOLO26x через WBF | mAP50 **0.665** на DENTEX (по отдельности 0.647 и 0.592). Детектор зубов с номерами FDI — mAP50 0.96 |
| **Интраоральные сканы** | STL/OBJ/PLY | DGCNN-подобная, чистый PyTorch | mIoU **0.9366** на Teeth3DS |

Поверх масок — слой находок: это **геометрия, а не ещё одна сеть**. Расстояние
корня до нижнечелюстного канала и до пазухи, уровень костной ткани мезиально и
дистально, ретенция, реставрации, эндодонтический статус, прикус по сканам.
Находки сворачиваются в план лечения по этапам, и порядок этапов взят из
реального плана клиники, а не придуман.

Экраны демо: `/patients` — список пациентов, `/cbct/<кейс>` — разбор КЛКТ,
`/2d` — панорамы, `/ios` — сканы, `/studies/<id>` — исследование, `/profile` —
профиль врача. Каждый экран адресуется ссылкой: врачу можно отправить
`/cbct/client4/sp?tab=tooth&tooth=13`, а не инструкцию «нажмите сюда, потом
сюда».

## Главное решение: основание вместо процента уверенности

У находки **нет** процента уверенности, и это выбор, а не недоделка. Процент —
это вероятность, а вероятности у нас нет: находки считаются геометрией по
маске, а разметки рентгенолога, на которой процент можно было бы
откалибровать, в проекте нет. Нарисованные «87%» врач не может ни проверить,
ни оспорить.

Вместо него каждая находка несёт **основание** — что измерено, сколько, при
каком пороге и с какой оговоркой:

> расстояние корень → канал 1.2 мм; контакт ≤0.5, близко ≤2.0; воксель 0.31 мм

Это проверяется прямо на срезе. По той же причине степень убыли кости
называется от нашей собственной выборки («выше 97% участков»), а не клинически
(«тяжёлый пародонтит»): первое — проверяемое утверждение об измерении, второе —
утверждение о болезни, и прав на него нет.

## Чего система не умеет — и почему

Этот список такая же часть продукта, как и предыдущий. Каждый пункт закрыт
замером, а не предположением; разбор — в `CLAUDE.md`.

| Не умеем | Упирается в |
|---|---|
| Кариес на КЛКТ | металлические артефакты и разрешение. Это задача панорамы и прицельного снимка |
| Стадию пародонтита по классификации 2018 | по определению требует зондирования и потери прикрепления. Отдаём миллиметры, долю длины корня и перцентиль выборки |
| Объём пазухи, утолщение слизистой | **разметку датасетов**: в эталоне пазуха размечена на 10% объёма. Решается своей разметкой, не другой моделью |
| ВНЧС | поле зрения: сустав выше кадра наших снимков. Решается протоколом съёмки |
| Класс кости D1–D4 | единицы Хаунсфилда на КЛКТ невосстановимы: ошибка на 13 аппаратах 35..1562 — шире всего диапазона. Отдаём долю костной ткани |
| Число корней и каналов по маске | маска сращивает корни у шейки и крошится у апекса. Закрыто отрицательно, вернётся с лучшей сегментацией |
| Качество пломбирования канала | зазор до апекса одинаков у пролеченных и живых зубов — это предел маски, а не недопломбировка |

Все пороги и правила помечены `draft`: врачом они не подписаны.

## Как запустить

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt
.venv/Scripts/python.exe research/scripts/demo_server.py --port 7861
```

Или `start_demo.bat`. Открыть http://127.0.0.1:7861

**Сначала прочитайте [SETUP.md](SETUP.md).** В репозитории нет весов моделей
(9.7 ГБ), датасетов (152 ГБ) и снимков клиники (медицинские данные), поэтому
после `git clone` инференс не работает — и это не поломка. Всё остальное
работает: 3D-вьюер, находки, план лечения, PDF, карточки пациентов считаются
геометрией по уже готовому кейсу. Такой кейс лежит в репозитории —
`fixtures/cbct_pair001/`, из публичного набора под CC BY 4.0, и подхватывается
при старте сам.

## Карта репозитория

```
research/          2D-трек: DENTEX, YOLO, ансамбль + демо-сервер и весь фронт
  scripts/           demo_server.py, cbct_*.py, ios_*.py, annotate_server.py
  scripts/demo_static/  интерфейс врача (одностраничный вьюер, карточки, профиль)
research_3d/       КЛКТ: nnU-Net, датасеты, кейсы, разметка каналов
research_ios/      интраоральные сканы: сегментация, прикус, находки
fixtures/          готовый кейс КЛКТ для разработки без моделей
plan/              спецификация продукта, статус, материалы к защите
docs/              справочное: дорожная карта, анализ конкурента, архив планов
materials/         материалы хакатона: условия, брифинги, расшифровки
site/              прототип интерфейса от команды
CLAUDE.md          рабочий журнал: замеры, пороги, отрицательные результаты
```

`src/` нет: production-кода пока не существует, всё живёт в research-треках.

## Данные и лицензии

Обучающие наборы в репозиторий не входят — ни по объёму, ни по лицензиям.
Полный перечень с лицензиями и ограничениями — в `plan/defense.md` и
`docs/ROADMAP.md`. Коротко: DENTEX (2D-патологии), ToothFairy2/3 (КЛКТ,
некоммерческая), DentVoxel (КЛКТ, CC BY 4.0 — используется **только** как
внешняя проверка, не для обучения), Pulpy3D (пульпа), Teeth3DS и Bits2Bites
(сканы), figshare 26965903 (пары скан+КЛКТ, CC BY 4.0), Zenodo 15487430
(состояния зубов на панорамах, CC BY 4.0).

Снимки и карточки пациентов клиники машину не покидают: `data/`,
`research_3d/web_cases/`, `research/example/` и соответствие «кейс → человек»
перечислены в `.gitignore` с причинами. Имя человека не попадает ни в код, ни в
комментарии, ни в документацию.
